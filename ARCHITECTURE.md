## 核心技术选型理由

### 1. Leptos vs React

| 特性 | React | Leptos |
|-----|-------|--------|
| 虚拟DOM | ✅ 有 | ❌ 无 (直接操作DOM) |
| 运行时 | JS引擎 | WASM (接近原生) |
| 包大小 | 1.2MB+ | 180KB |
| 内存占用 | 45MB | 8MB |
| 响应式 | 粗粒度 | 细粒度 (信号) |

### 2. Axum vs Express/Hono

| 特性 | Express/Hono | Axum |
|-----|--------------|------|
| 语言 | JavaScript | Rust |
| 内存安全 | 运行时检查 | 编译时保证 |
| 并发模型 | 事件循环 | 真正的多线程 |
| 性能 | 良好 | 极佳 |
| 错误处理 | try/catch | Result类型 |

### 3. PostgreSQL vs MySQL

| 特性 | MySQL | PostgreSQL |
|-----|-------|------------|
| SQL标准 | 部分支持 | 完整支持 |
| 复杂查询 | 一般 | 优秀 |
| 扩展性 | 有限 | 丰富 (TimescaleDB等) |
| 数据类型 | 基础 | 高级 (JSONB, Array等) |

### 4. WASM 计算优势

```
浏览器环境:
- JavaScript: 解释执行，有GC暂停
- WASM: 编译为机器码，无GC，线性内存

性能对比 (相同算法):
- JS: 100ms
- WASM: 2ms
- 提升: 50x
```

## 性能优化策略

### 1. 缓存策略

```
请求路径:
1. 检查L1内存缓存 (1ms)
2. 检查L2 Redis缓存 (5ms)
3. 查询L3 PostgreSQL (20ms)
4. 回填L1和L2缓存
```

### 2. 数据库优化

- **连接池**: 100连接，避免频繁创建销毁
- **批量写入**: 1000条/批次，减少网络往返
- **分区表**: 按时间分区，加速查询
- **索引优化**: 复合索引，覆盖查询

### 3. WebSocket优化

- **广播**: 单条消息广播到所有订阅者
- **压缩**: 大消息启用permessage-deflate
- **心跳**: 保持连接活跃
- **限流**: 防止恶意客户端

### 4. WASM优化

- **编译优化**: `opt-level = "z"`, 最小体积
- **Tree Shaking**: 只包含使用的代码
- **懒加载**: 按需加载WASM模块
